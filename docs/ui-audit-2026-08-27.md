# DeerFlow Android 真机 UI 审计

日期：2026-08-27  
设备：HONOR APH-AN00，Android 16 / API 36，1216 × 2640，density 560  
版本：DeerFlow 1.2.0，versionCode 19  
范围：视觉与易用性；不包含专项无障碍、性能和 TalkBack 审计  
方式：安装当前 `assembleDebug`，通过 ADB 与语义控件导航，采集真机截图并对照 Compose 源码

## 结论摘要

当前版本已经具备稳定的主流程：聊天、抽屉、模型/运行模式菜单、运行详情、浏览器、Agents、定时任务、技能、记忆和个人设置均可进入；Honor 真机上 API 36 的玻璃采样、抽屉透视和 in-composition 菜单均能实际渲染。

最值得优先处理的是输入区和高信息密度弹层：首屏快捷操作 chip 在右侧截断，输入框占位文案被迫换成两行；玻璃菜单、运行详情和浏览器 sheet 的背景内容透出较多，前景与背景竞争；记忆摘要和技能描述没有足够的摘要层级。它们不会阻塞使用，但会直接影响首次观感、扫描效率和长时间阅读体验。

本次未人为构造新的 Markdown 表格/多级标题回复，因此不对表格在该真机上的最终视觉效果下结论；已有会话中的消息、工具卡片、链接、来源卡片和 Token 信息已检查。

## 优先级定义

- **P1**：影响首屏理解、输入、阅读或核心任务效率，建议近期处理。
- **P2**：不阻塞任务，但影响一致性、扫描和完成度，适合随下一轮 UI 调整处理。
- **P0**：本次未发现阻塞使用的视觉/易用性问题。

## P1 问题

### P1-01 快捷操作 chip 在首屏右侧截断

**证据**：`.tmp/audit/01_home.png`、`.tmp/audit/15_drawer_again.png`。第三个「写作」chip 在屏幕右侧只显示了部分文字，字符被切在 chip 边界处。虽然当前实现支持横向滚动，但初始状态看起来像布局损坏，也没有明确的“还有更多”提示。

**源码**：`app/src/main/java/com/deerflow/mobile/ui/ChatScreen.kt:1889-1927` 使用 `HorizontalFloatingToolbar`，内部 `Row` 使用 `horizontalScroll`；chip 本身位于 `app/src/main/java/com/deerflow/mobile/ui/glass/GlassComponents.kt:213-247`。

**建议**：

1. 保留横向滚动时，为 Row 增加明确的末端内边距，确保最后一个 chip 可以完整滚入视口；初始布局不要把一个中文字切在半字符位置。
2. 在右侧增加很轻的渐隐提示或滚动状态提示；如果快捷操作数量通常较多，优先考虑 `LazyRow` + content padding。
3. 结合屏幕宽度只展示 2 个完整 chip 和一个“更多”，或把快捷操作分为最常用项与可展开项，避免首屏显得拥挤。

### P1-02 输入框占位文案在荣耀小屏上换成两行

**证据**：`.tmp/audit/01_home.png`、`.tmp/audit/28_composer_keyboard.png`。空输入框显示「给 DeerFlow 发消 / 息」，视觉上像文本布局异常；键盘出现后仍然如此。当前可用输入宽度被左右 48dp 图标槽和发送按钮进一步压缩。

**源码**：`app/src/main/java/com/deerflow/mobile/ui/ChatScreen.kt:1608-1699`。占位文字来自 `app/src/main/res/values-zh-rCN/strings.xml:194` 的 `message_deerflow`，TextField 同时使用 leading/trailing icon 和 `maxLines = 6`。

**建议**：

1. 中文占位文案改为更短的「发消息」或「输入消息」，把完整语义保留在输入框的 accessibility/content description 中。
2. 占位状态强制单行，避免空态因为 placeholder 自动换行改变视觉重心。
3. 真机上重新比较“附件 + 输入 + 润色 + 发送”的宽度分配；如果保留完整文案，应减少非必要的横向占用，而不是继续压缩输入区。
4. 键盘打开时保留当前上移行为，但让 composer 的最小高度保持稳定，避免输入区与内容区反复跳动。

### P1-03 玻璃菜单和信息型 sheet 的背景竞争仍然偏强

**证据**：`.tmp/audit/10_model_menu_retry.png`、`.tmp/audit/11_thinking_menu.png`、`.tmp/audit/14_after_sheet.png`、`.tmp/audit/30_browser.png`。真机玻璃效果确实生效，但模型/思考菜单、运行详情和浏览器 sheet 中，后面的消息文本和 composer 仍清晰透出。运行详情打开后，指标和事件文字与底层对话同时争夺注意力；浏览器加载态则能看到整页底层内容。

**源码**：

- `app/src/main/java/com/deerflow/mobile/ui/glass/GlassMenuHost.kt:115-125` 的“modal scrim”只负责拦截点击，没有绘制可见的 scrim。
- `app/src/main/java/com/deerflow/mobile/ui/glass/GlassMenu.kt:155-177` 使用透明/低 alpha veil 作为菜单底。
- `app/src/main/java/com/deerflow/mobile/ui/glass/GlassComponents.kt:90-110` 的 `GlassModalBottomSheet` 使用 `glassFrosted`，没有针对信息密度提高底色不透明度。

**建议**：

1. 下拉菜单使用很轻的自适应 scrim（例如按主题使用约 0.08-0.16 的暗化层），重点是降低底层文字的竞争，不要把液态玻璃改成不透明弹窗。
2. 运行详情、浏览器这类信息密集型 sheet 使用更高 alpha 的 frosted veil；保留边缘高光和玻璃形态，把可读性优先级设在透视强度之上。
3. 菜单/弹层中做一次长标题、长 URL 和长中文消息的对比度回归，至少覆盖深色主题和浅色主题。
4. 将“装饰型玻璃”和“工作型玻璃”分开调参：顶栏可以更透明，运行详情、输入和浏览器内容应更稳定、更少透出。

### P1-04 记忆摘要默认为整段展开，扫描成本高

**证据**：`.tmp/audit/22_memory_loaded.png`。工作上下文、个人上下文和当前关注均以大段正文直接铺开，单个摘要占据很高的纵向空间；用户需要阅读大量文字后才能找到下一个分区。

**源码**：`app/src/main/java/com/deerflow/mobile/ui/MemoryScreen.kt:366-384` 的 `MemorySummaryRow` 直接渲染完整 `summary`，没有 maxLines 或折叠状态。

**建议**：

1. 列表默认展示 3-4 行摘要，超出后显示省略号和「查看详情」。
2. 点击摘要打开详情 sheet，完整内容、更新时间和来源放在详情页展示。
3. 保留当前「全部 / 事实 / 摘要」筛选；在摘要列表中增加更新时间或内容类型的轻量标识，帮助用户快速判断是否需要打开。
4. 对“当前关注”这类高频内容可以提供默认展开记忆，但不要让所有摘要同时展开。

### P1-05 技能弹层被长英文描述主导

**证据**：`.tmp/audit/20_skills.png`。`academic-paper-review` 的英文描述占据整个首个卡片，第二个 `animate` 只在底部露出一小段；在中文用户界面中，长英文技能说明尤其影响列表扫描和选择。

**源码**：`app/src/main/java/com/deerflow/mobile/ui/WorkspaceDrawer.kt:995-1045`，其中 `1014-1023` 直接渲染完整 `skill.description`；网格固定为 `height(440.dp)`。

**建议**：

1. 列表卡片只展示 3-4 行描述和 category/status，完整说明放到技能详情页。
2. 手机宽度下优先使用单列紧凑列表，或者限制卡片最大高度；不要让一个技能的自然高度挤走其他技能。
3. 把“启用/停用”作为稳定的尾部操作，同时提供“查看详情”，使用户无需展开长文才能完成选择。
4. 对网关返回的英文名称/说明允许保持原文，但通过摘要、分类和固定高度控制信息密度。

## P2 问题

### P2-01 抽屉时间戳过长，不利于快速扫描

**证据**：`.tmp/audit/16_drawer.png`。每条最近会话都显示完整 `2026-08-27 13:39:32`，在移动端占据较多横向空间，也不如“今天 13:39 / 昨天 / 8月26日”直观。

**源码**：`app/src/main/java/com/deerflow/mobile/ui/SharedComponents.kt:103-112` 的 `toDisplayTime()` 固定输出 `yyyy-MM-dd HH:mm:ss`；抽屉在 `WorkspaceDrawer.kt:374-384` 使用该格式。

**建议**：按时间距离采用分级格式：今天显示时间，昨天显示“昨天”，本周显示月日，更早才显示年份；详情页再保留完整时间戳。这样可同时保留精度和列表可读性。

### P2-02 中文界面的 Agents 命名不一致

**证据**：抽屉和页面标题均显示英文 `Agents`，其它入口为「任务 / 技能 / 记忆」；`.tmp/audit/16_drawer.png`、`.tmp/audit/17_agents.png` 可见。

**源码**：`app/src/main/res/values-zh-rCN/strings.xml:14` 和 `:316` 的 `tab_agents` / `agents_title` 仍为 `Agents`。

**建议**：产品层面二选一并全局统一：中文用户使用「智能体」，或明确把 `Agents` 作为产品术语并在首次出现处提供解释。抽屉、页面标题、按钮和详情页应使用同一命名。

### P2-03 对话页模型名在多按钮顶栏中截断得过早

**证据**：`.tmp/audit/05_conversation_loaded.png`、`.tmp/audit/07_conv_top.png`。对话页顶栏显示 `GPT-5.6 T...`，用户无法直接区分 Terra、Sol 等相近模型；首页空间较宽时则能显示完整名称。

**源码**：`app/src/main/java/com/deerflow/mobile/ui/ChatScreen.kt:843-910` 将模型 selector 限制为 `widthIn(max = 152.dp)`；`TopSelector` 在 `978-1005` 对名称使用单行 ellipsis。

**建议**：保留当前可压缩布局，但为按钮使用更短的展示别名（例如 `Terra`），在菜单标题或选中项中显示完整 provider/model 名；或者在长按/点击后的菜单头部显示完整名称。不要通过压缩其它固定操作来换取模型名全量显示。

### P2-04 子页面顶栏与聊天顶栏的视觉语言不完全统一

**证据**：聊天页使用圆形玻璃按钮和胶囊 selector；Agents、任务、记忆、个人页使用矩形 `GlassTopAppBar`。`.tmp/audit/17_agents.png`、`.tmp/audit/19_tasks.png`、`.tmp/audit/22_memory_loaded.png`、`.tmp/audit/23_profile.png` 对比明显。

**源码**：聊天顶栏位于 `app/src/main/java/com/deerflow/mobile/ui/ChatScreen.kt:747-840`；通用顶栏位于 `app/src/main/java/com/deerflow/mobile/ui/glass/GlassComponents.kt:61-79`。

**建议**：统一页面级顶栏的高度、左右 inset、返回按钮规格和标题基线；允许聊天页保留 selector，但将其余页面的 action 间距、玻璃边缘和滚动后的处理统一到同一套 token。

### P2-05 个人页的分组层级在深浅主题中偏平

**证据**：`.tmp/audit/23_profile.png`、`.tmp/audit/26_light_theme.png`。深色主题中账户/连接项目呈大块矩形，浅色主题中背景和列表底色接近，静态信息与可点击设置的区分不够强。

**源码**：`app/src/main/java/com/deerflow/mobile/ui/ProfileScreen.kt:197-245` 的多个 `ListItem` 仅设置 frosted container；`ProfileSection` 在 `ProfileScreen.kt:780-784` 没有额外分组形状或间距。

**建议**：用 section 间距、标题和细分隔线建立层级，交互项使用统一的 trailing affordance；静态账户信息可降低表面强调。浅色主题降低大面积白色 veil 的覆盖，保留足够的背景/容器亮度差。

### P2-06 空任务页缺少就地行动入口

**证据**：`.tmp/audit/19_tasks.png`。空态说明清楚，但用户需要注意右上角的小 `+` 才能创建任务；空态本身没有行动按钮。

**源码**：`app/src/main/java/com/deerflow/mobile/ui/TasksScreen.kt:104-110` 只渲染 `EmptyState`；创建入口在顶栏 `TasksScreen.kt:132-147`。

**建议**：在空态下增加「创建定时任务」主按钮，同时保留顶栏 `+`；按钮可以只在空态出现，避免有任务时重复占空间。

### P2-07 浏览器加载态缺少下一步动作

**证据**：`.tmp/audit/30_browser.png`。浏览器 sheet 能明确显示「正在等待浏览器画面」，但等待时主要是空的深色 viewport；没有明显的重试、关闭并返回或连接失败处理入口。

**源码**：`app/src/main/java/com/deerflow/mobile/ui/BrowserLiveSheet.kt:132-143` 设置近全屏 sheet；`BrowserLiveSheet.kt:397-404` 仅根据状态显示 loading/no-page 文案。

**建议**：在连接超时或 Error 状态提供「重试」和错误原因；Connecting 状态可显示连接阶段和取消动作。`about:blank` 作为地址初始值时，应配合更明确的空页说明，避免用户误以为已经打开了空白网页。

## 已验证的优点

- Honor APH-AN00 / Android 16 真机上，液态玻璃不是空白回退：抽屉、模型菜单和思考模式菜单都能看到真实的背景采样和边缘效果。
- Workspace 抽屉的内容结构完整：身份、主导航、最近会话、搜索和新建会话集中在一个流程内；背景模糊在 `.tmp/audit/16_drawer.png` 中可见。
- 对话页在已有会话中，用户消息、工具调用、助手正文、来源卡片、链接和 Token 摘要层次基本清楚；`.tmp/audit/05_conversation_loaded.png`、`.tmp/audit/07_conv_top.png` 可作为基线。
- 模型菜单包含完整模型名和选中态，思考菜单提供模式说明和推理深度信息；功能信息完整，主要问题是透明度和密度，而不是缺少功能。
- 主题切换可用，浅色/深色/跟随系统的入口清楚；浅色主题的主要问题是表面层级偏平，不是文字不可读。

## 建议实施顺序

1. **第一轮**：修复 composer 占位文案和快捷 chip 的初始截断；这是首屏可见、改动范围小、收益最高的部分。
2. **第二轮**：为菜单和信息型 sheet 建立两档 veil/scrim token，并在真机上回归长消息、长 URL、运行详情和浏览器 loading。
3. **第三轮**：将记忆摘要、技能描述统一改为“摘要列表 + 详情页”，同步优化时间戳和空任务 CTA。
4. **第四轮**：统一 Agents 中文命名、子页面顶栏 token，以及个人页深浅主题的分组层级。
